## 摘要（三句话）

1. **你的记录只在这台电脑上**：九格手记没有账号、没有云端、没有同步，全部内容以明文 JSON 存在本机数据目录，我们不收集、不上传、也无法访问。
2. **只有两处会联网，都可关闭**：首页天气会向 ipwho.is 与 Open-Meteo 发 GET 请求（会暴露你的出口 IP 与城市经纬度）；ActivityWatch 时间源只连本机回环 `127.0.0.1`。两者都能在设置里关掉，关掉后其余功能不受影响。
3. **没有统计 SDK、没有广告、没有崩溃上报**：本机有一份使用指标（只记日期与计数，不含任何正文），默认开启、可随时关闭、不进备份、不出本机。

## 一、适用范围

本政策适用于「九格手记」Windows 桌面版客户端软件（以下简称「本软件」）在你本机运行期间对数据的处理。

**不适用**于以下情形：

- 你自行把导出的 `.jiuge` 备份文件、截图或文本上传到网盘、邮件、即时通讯工具等第三方服务——那部分由该第三方服务自身的隐私政策约束；
- 你通过本软件打开的外部网页或第三方软件（本软件不内嵌浏览器内核访问外部页面，也不拉起第三方登录）。

## 二、我们不做的事（否定清单）

为避免歧义，以下事项**明确不做**，且已在代码层面做了结构性限制，不是口头承诺：

| 不做的事 | 代码层面的依据 |
|---|---|
| 不注册账号、不采集手机号/邮箱/身份信息 | 全仓无登录、无鉴权、无用户表；IPC 白名单无任何「上传用户」通道 |
| 不把日记内容发往任何服务器 | 渲染层（界面代码）零网络请求；主进程联网代码仅存在于 `src/weather/client.js` 一个文件，且只发 GET 公开气象数据 |
| 不做使用统计上报、崩溃上报、A/B 实验 | 无任何统计/崩溃 SDK；依赖清单只有 Electron 与打包工具，运行期零第三方依赖 |
| 不投放广告、不做用户画像、不跨应用追踪 | 无广告组件、无设备指纹、无 IDFA/ID 类标识 |
| 不读取你的其他文件 | 仅在你主动添加「链接型附件」时记录该文件的路径、大小与修改时间，**不复制、不读取内容** |
| 不采集窗口标题、不记录你的键鼠 | 时间源只从本机 ActivityWatch 读取已聚合的应用与时长，不读窗口标题；不设任何全局键盘钩子 |
| 不自动更新、不后台下载 | 无更新器；升级由你手动下载覆盖 |

## 三、数据存在哪里

### 3.1 数据目录

默认位置：`%APPDATA%\<应用名>\jiuge-data\`（Windows 便携版首次运行时由系统按应用名创建）。

**真实路径以软件内「设置 → 数据中心」显示的路径为准**，该处会直接列出当前生效的目录，并可在底栏「打开数据目录」一键打开。

### 3.2 目录内的文件

| 文件/目录 | 内容 | 是否含正文 | 是否进入备份 |
|---|---|:--:|:--:|
| `store.json` | 全部业务数据（九格日记、GTD、梦想、学习、语料库、关系、阅读、账本、自由记录等），单个 JSON 文件 | 是 | 是 |
| `journal.jsonl` | 写前日志（WAL），逐条记录历次写入的键与值，用于崩溃恢复；**只追加、不自动清理**，因此会随使用时长增大，且长期保留历史修改内容 | 是 | 否 |
| `snapshots\<id>\` | 数据快照（手动/自动备份），每份为对应时刻的完整副本 | 是 | —（快照本身即备份） |
| `metrics.log` | 本机使用指标（JSONL），**只含日期、计数与耗时** | **否** | **否** |
| `metrics.off` | 指标关闭标记文件（存在即视为关闭） | 否 | 否 |

> 说明：`metrics.log` 独立于 `store.json`，因此导出备份时**结构上不可能**把指标数据带出去；这一点有自动化断言守着（`golden` 用例「metrics 不落 store.json、不写正文」）。

### 3.3 敏感性提示

**`store.json` 是明文 JSON，没有整库加密。** 任何能读取该目录的程序或人（同机其他账户、远程控制软件、取证工具、你借出的电脑）都能直接读到全部内容。

本软件提供的是「单条加密」而非「全库加密」：

- 你可以对**单条**记录设置口令，加密算法 **AES-256-GCM**，密钥由口令经 **scrypt（N=16384）** 派生；
- **口令不存储、不上传、不写进任何返回值**，因此**忘记口令即永久无法恢复，本软件不提供找回、重置或后门**；
- 未加密的其他记录仍是明文。

**建议**：在共用或可能被他人接触的设备上，启用 Windows 全盘加密（BitLocker）；涉密内容不要存放在任何个人记录软件中。

## 四、会离开这台机器的数据

**只有天气一项。** 除此之外，本软件不向任何服务器发送任何数据。

### 4.1 天气（默认开启，可关闭）

实现位于 `src/weather/client.js`，三条硬边界写在文件头部：**只发 GET**、**只连三个白名单域名**（其他 host 直接拒绝）、**不携带任何用户内容**（不发日记、不发机器名、不发九格里的任何字段）。

| 域名 | 请求示例 | 发送了什么 | 为什么需要 | 对方用途 |
|---|---|---|---|---|
| `ipwho.is` | `GET https://ipwho.is/?lang=zh-CN` | 你的**出口 IP**（HTTP 协议层面必然暴露）、语言偏好 `zh-CN` | 按 IP 粗略判断城市，免去手动填城市 | 由 ipwho.is 按其政策处理。本软件**只从响应中读取城市名与经纬度**，运营商、邮编、旗帜等字段一律不读、不传、不落盘，**IP 本身不保存** |
| `api.open-meteo.com` | `GET https://api.open-meteo.com/v1/forecast?...&latitude=..&longitude=..` | **城市经纬度（保留 4 位小数）**、请求的要素与单位 | 取当前天气与预报 | 由 Open-Meteo 按其政策处理 |
| `geocoding-api.open-meteo.com` | `GET https://geocoding-api.open-meteo.com/v1/search?name=<城市名>` | 你手动输入的**城市名称** | 手填城市时换算成经纬度 | 同上 |

补充边界（均可复核）：

- 两个提供方**均免注册、免 API Key**，因此本软件不持有、也不传输任何密钥；
- 请求**不携带 Cookie、不携带设备标识、不携带安装 ID**；
- 单次请求超时 **4.5 秒**，响应体上限 **256 KB**，User-Agent 固定为 `jiuge-desktop/1.0 (weather; +local)`；
- 你手动指定城市后，请求中只有该城市经纬度，不再需要 IP 定位；
- **关闭开关后 `src/weather/client.js` 不会被调用**，不会有任何请求发出；
- 本软件**不保存** ipwho.is 返回的 IP 相关信息；`md_weather` 只保存偏好（是否开启、模式、城市名）与最近一次天气缓存，且**该键不进入备份与导出**（换机器重新拉取即可）。

### 4.2 本机时间源 ActivityWatch（默认关闭，需你手动接入）

- 目标地址**只允许回环**：`127.0.0.1` / `localhost` / `[::1]`，默认 `127.0.0.1:5600`，非回环地址一律拒绝（见 `src/worktime/board.js` 的 `HOST_RE`）；
- 只做**只读订阅**，代码里没有任何写回 ActivityWatch 的函数（不建 bucket、不打 tag）；
- 数据不出本机，也不经过任何公网服务器；
- 不接入该功能时，本软件不会尝试连接该端口。

### 4.3 如何关闭

「设置 → 数据中心 / 首页天气胶囊」均有开关。关闭后：

- 不再发起对应请求；
- 已缓存的天气数据保留在本机（可随 `store.json` 一并删除）；
- 今日概况中的天气行显示为不可用状态，其余功能不受影响。

## 五、本机使用指标（`metrics.log`）

### 5.1 为什么有它

产品需要判断「是否真的有人每天在用」，而这类判断不能靠猜。指标只写在你的电脑上，用于你在「设置 → 数据中心」自行查看使用情况（如周有效记录天数）。

### 5.2 记录了什么

共 **7 类事件**，字段为**白名单制**——不在白名单内的键一律丢弃：

| 事件 | 记录字段 | 说明 |
|---|---|---|
| `app_start` | `ts`, `version` | 启动时间、版本号 |
| `entry_save` | `ts`, `date`, `ms` | 保存日期、本次保存耗时（毫秒） |
| `search_use` | `ts`, `mode` | 检索方式（普通/拼音） |
| `migrate` | `ts`, `stage` | 迁移阶段（不含迁移内容） |
| `quick_capture` | `ts`, `date` | 速记落日日期 |
| `snapshot_restore` | `ts`, `id` | 回滚到哪个快照 ID |
| `backup_run` | `ts`, `reason` | 备份触发原因（自动/手动） |

### 5.3 明确不记录什么

**任何正文。** 代码里有第二道防线：`text`、`content`、`body`、`note`、`title`、`raw`、`payload` 七个字段名在写入前被**强制删除**，即使调用方误传也写不进去。这条不只是承诺，有自动化断言用「硬塞正文」的方式验证过。

同时不记录：IP、设备名、用户名、窗口标题、按键、鼠标轨迹、崩溃堆栈。

### 5.4 你的控制权

| 你想要的 | 怎么做 |
|---|---|
| 关闭指标 | 设置 → 数据中心 → 关闭「本机使用指标」开关（生成 `metrics.off`） |
| 删除已记录数据 | 直接删除数据目录下的 `metrics.log` 与 `metrics.off` |
| 导出查看 | 数据中心提供导出，导出的是本机同款 JSONL |
| 确保备份里没有它 | 无需操作——指标不在 `store.json` 内，备份结构上带不走 |

**默认开启**（首次运行即记录），关闭后立即停止写入，已写入的历史记录不会自动删除，由你自行处置。

## 六、导出、备份与回滚（数据可携带）

- **导出**：可把全部数据键打成 `.jiuge` 文本容器（带 `kind`/`version`，可解析、可校验、可还原），也可导出 Markdown；
- **快照**：可手动或按计划创建数据快照，并在「设置 → 数据中心」看到可回滚版本列表；
- **回滚**：选择某一版本回滚前，系统会**先为当前状态强制留一份安全快照**（回滚本身也可回滚），并需要两步确认；
- **离开本机即由你负责**：导出的文件不受本政策保护，请自行加密存放或存入选定的可信介质。

## 七、删除数据

- **删除全部数据**：关闭软件后删除数据目录（`%APPDATA%\<应用名>\jiuge-data`）即可彻底删除。删除后不可恢复，且**没有任何服务端副本可以找回**——因为不存在服务端。
- **删除单条记录**：在软件内删除对应内容即可。**请注意**：历史快照（`snapshots\`）与写前日志（`journal.jsonl`）中可能仍保留该条内容的旧副本——WAL 只追加、不自动清理。如需清除快照中的旧副本，请删除 `snapshots\` 下相应快照；**若需彻底清除全部历史修改痕迹，最稳妥的做法是先导出备份，再按上一条删除整个数据目录**（我们不建议单独删除 `journal.jsonl`：它是崩溃恢复依赖，单独摘除可能影响异常退出后的数据回放）。
- **卸载**：便携版无安装程序，删除 exe 与数据目录即完成卸载；数据目录**不会**被自动清理（这是有意设计，避免升级或误删导致数据丢失）。

## 八、安全边界（我们不承诺什么）

诚实说明本软件**不能**提供的保障：

1. **不承诺整库加密**：除你主动加密的单条记录外，数据是明文。
2. **不承诺防篡改**：本机拥有管理员权限的程序可以修改 `store.json`，软件只能通过校验和/快照对比发现问题，无法阻止。
3. **不承诺代码签名**：当前发布的便携版**未做数字签名**，Windows SmartScreen 可能提示「未知发布者」。请仅从官方渠道获取，并核对页面公布的 SHA256。
4. **不承诺防勒索软件**：若系统被勒索软件加密，本机快照同样会被加密。**异地/离线备份不可替代。**
5. **不承诺多设备同步**：本软件无云同步。多设备之间只能通过手动导出/导入 `.jiuge` 文件迁移，且**后导入者覆盖先导入者**，请先备份再迁移。

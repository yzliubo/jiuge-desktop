>
> 这是「换壳不换脑」等价移植在**状态更新语义**上的根本张力，属**类别问题，不是补一行能根除的**：即便按 §2.2 ① 的最小方案修好 D01，只要运行时仍以「数组整体变化」为唯一刷新信号，上游任何一次「只改外层标量 / 只 patch 一格 / 刻意不重设数组」的写法都会重新触发同类缺陷。这也解释了**为什么 90/90 全绿却仍有已确认缺陷**、以及**为什么 D05「自制运行时只覆盖 17 类语法/组件、无行为回归基线」必须定为 P0**：现有验证只证明「源码文本一致 + 静态断言存在」，没有任何一层在验证「桌面运行时的状态更新语义与小程序等价」。根治方向是引入依赖追踪或 DOM 快照回归基线，而不是逐个补 class 断言。

**最小修复方案（架构师 v1.4 给出，本报告采纳并写入 D01 偿还成本）**：`syncLoop()` 的短路分支**不要直接 `return`**，改为遍历 `loop.items` 对每个 `inst` 调 `refreshInst(inst)`。

### 7.1 交付过程中修过的 4 类缺陷：哪类本可以在设计期避免

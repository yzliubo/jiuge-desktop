**价值（对日记类产品，这些边界是核心资产，不是妥协）**：

- **信任**：极私密内容不出本机、无账号、无遥测、无服务停运风险、断网可写，是产品差异化最硬的一条。
- **可携带 / 可退出**：数据是一个用户自己能打开的 `store.json`，且导出三种格式（Markdown 可直入 Obsidian / Logseq / 思源），产品甚至把「按 3-2-1 原则留存」写进设置页（`settings.wxml:133`）——**主动把数据主权交给用户**，这点比多数同类产品做得好。

**代价（必须如实说清）**：

| 代价 | 说明 |
|---|---|
| 多设备 / 换机只能手工搬运 | 无同步 = 全部依赖「导出文件 → 导入文件」，而**这条链路恰好是本次最弱的一环**（§7 问题1+2）。边界的代价与本次的短板完全重叠，这是最该警惕的结构性巧合 |
| 无云端兜底 | 硬盘损坏 / 误删 `store.json` 即全部丢失；无自动备份，仅「打开数据目录」只读入口 + 导入前快照 3 份。风险 100% 转嫁给用户，而用户又被 §7-问题1 误导着「以为备份好了」 |
| 无自动更新 | `README.md §9` 明确无更新器，用户拿到静态版本；未来修问题需手动换 exe（数据与程序分离，换版本成本低但用户不易感知） |
| 未签名 | SmartScreen 首启拦截，是「不进商店 / 不做分发」的直接副作用（已知限制，不算问题，但计入旅程流失） |

> **定位结论**：边界守得干净，且边界本身就是产品定位。**代价全部集中在「数据搬运」这一条链路上，而这条链路正是本次唯一新增能力（文件导入 / 另存）所在之处**——所以产品上最该投入的不是加功能，而是把这条链路的引导、文档、反馈做扎实。这与 §0、§4 的结论三者一致。

## 10. v1.1 增补：数据主权信息缺口与跨报告口径收敛
